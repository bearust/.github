# Security Policy

## Supported Versions

We advise users to run or update to the most recent release of each Bearust project. Only the latest release line receives security fixes. Older versions may not have all enhancements and/or bug fixes applied to them.

## Reporting a Vulnerability

Please **do not** open a public issue, discussion, or pull request for a suspected vulnerability. Instead, use GitHub's private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability**.

Include in your report:

- Affected repository, component, and version/commit
- Steps to reproduce or a minimal proof of concept
- Expected vs. actual behavior and the suspected impact
- Any relevant logs with secrets redacted

Reports are reviewed by the maintainers, who will confirm receipt, investigate, and coordinate a fix and disclosure timeline with you. Please allow reasonable time for a fix before any public disclosure, and avoid testing suspected vulnerabilities against deployments you do not own.

When sharing any diagnostic output, redact passwords, tokens, API keys, private keys, and session cookies.
